# 奇衡系列课程精读

本 skill 按系列持续迭代。课程进度以对应系列学习地图为准，历史样本与修订依据见 [references/evolution.md](references/evolution.md)。

## 定位与质量标准

用户把奇衡作为重要的二级市场入门老师，期待可以反复读、反复体会的精品课程资料。把这项偏好落实为耐心还原论证和教学细节，不将“最好的老师”写成已核实的排名，也不因此省略事实核验。

核心交付是**系列位置清楚、单课逻辑完整、感悟有根据、知识可以复习、变化可以追溯**。篇幅由教学密度决定，不以固定条数、字数或金句数量充当精品标准。

每次开始读取 [references/course-workflow.md](references/course-workflow.md)。首次建立系列或制作学习稿、笔记时读取 [references/editorial-guide.md](references/editorial-guide.md)。新增样本及出现方法、表达变化时读取 [references/evolution.md](references/evolution.md)。

## 先定位系列，再读单课

- 以主页 UID 与视频署名核实作者：[奇衡DK-CAPITAL](https://space.bilibili.com/473168952)。
- 核对作者维护的合集、系列、收藏夹、片头片尾与课间引用。收藏排序、推荐播放列表、发布时间、课程编号是不同信息，不能互相替代。
- 尊重原课程顺序；分清导论、正课、上下集、案例、答疑、补充和跨系列引用。没有证据记为“顺序待核”，不猜课号、不自动扩展分析全系列。
- 建立系列地图，但仅为已分析内容写知识结论；未分析课只列原链接、标题和状态。
- 同一视频只维护一份正文。属于多个系列时从多个索引引用，避免复制后出现不同版本。
- 不强制把后期商业、产业、读书、人生议题转成选股与买卖模板。按视频真正要解决的问题选择模块。

## 可复用脚本

优先使用 [scripts/video_pipeline.py](scripts/video_pipeline.py) 的 `fetch`、`transcribe`、`frames` 子命令执行下载、带时间轴转写与原始帧提取。参数、依赖及产物见 [course-workflow.md](references/course-workflow.md) 开头。脚本不写正式文章、不自动删除素材。

## 串行工作流

1. **确认来源与系列位置**：标题、UID、发布时间、时长、BVID、分 P/CID、可见性、系列名称与证据。
2. **获取全片证据**：主动获取可访问的视频/音频或可靠字幕；必要时本地转写，保留时间轴。执行 course-workflow 中从比巴卜迁移的取材步骤，先形成原始底稿并读完全片，再建立内部议题清单。
3. **文字底稿与核验**：还原概念、论证顺序、故事、类比、自我修正、反例、限定条件和未解问题；核对名词和决定结论的画面。区分作者说法与事实核验。
4. **证据门与冻结**：确认开场至结尾全部有效议题已阅读，中心论证无缺口；记录字幕范围、遗漏、修订、尚未解决的问题。将符合可用范围的正式文字材料写入后冻结，再制作或回改笔记。资料不全标为部分稿，不声称完整。
5. **精读笔记**：以核验后的底稿生成知识提炼、案例拆解、感悟和复习问题；不得用标题、弹幕、平台 AI 总结或熟悉的投资常识替代正文。
6. **系列更新与迭代判断**：更新地图、概念和跨课问题，检查是否出现值得修改 skill 的新证据。允许结论为“本课无需修改 skill”。
7. **入库校验**：检查链接、导航、证据对应关系与必要构建；每次分析完成并验收后，删除本次临时文件并清理空目录，遵守下文文件操作约束。

## 三类内容始终分开

1. **作者课程**：他讲了什么、怎样推导、条件是什么；故事的教学功能与史实真实性分开。
2. **外部核验**：姓名、书目、年份、事件与市场机制的核对。不能静默把作者口误改成正确说法，也不能把 ASR 错字判成作者口误。
3. **整理者理解与延展**：帮助初学者理解的解释、反例、感悟和练习，明确署明来源层次，不能冒充作者原话或未讲的规则。

对书籍解读再分清“原书内容”“奇衡转述”“奇衡批评/改造”。未直接读过原书相应章节，不把视频转述标作原书原话。

## 精品知识与感悟

- 重要知识讲清：**解决的问题 → 作者依据与推导 → 案例承担的作用 → 结论 → 适用条件与未说明之处**。不要压成无来源口号。
- 感悟讲清：**触发片段和时间 → 原有直觉 → 本课改变了什么理解 → 能做什么观察/练习 → 不能推得什么**。可以讨论认识论、学习方式、纪律和人生经验；避免鸡汤化与臆造用户经历。
- 出现课堂练习时，先保留题面、已知条件与当时可见信息，再分开展示作者解释和整理者延展；不提前用后续行情或弹幕替学生作答。
- 有价值的犹豫、矛盾、修正、类比和反问要保留。作者留下的悬念是系列学习接口，不能提前用其他老师的方法补上。
- 历史盈利案例不能直接证明方法有效。将“作者当时的判断”“事后结果”“整理者的理解”分开，不拿后来的走势替早期决策补证据。
- 学习材料不提供确定性买卖指令；涉及策略，保留等待、退出、失效及作者未交代的部分。

## 文字稿的可用范围

用户提供的视频、音频或字幕文本可依其请求完整整理，按原序轻度润色，不变成摘要。第三方链接本身不等于用户提供了全文；未经许可时不输出受版权保护视频的完整逐字稿或近似全文改写，交付明确标注的**时间轴学习稿（非逐字稿）与原创分析**，说明与完整文字稿的差距。不得以“整理稿”之名暗中转载全文。

时间轴学习稿覆盖全片的议题路线，但不逐句重现；仅保留必要的短引文。后台读完字幕不等于可以全文发布字幕。取得用户提供的原始材料后，可按相同证据与质量标准补足完整稿。

## 文件结构与目录管理

采用“人物首页 → 系列课程总目录 → 系列学习地图 → 精品笔记 / 文字稿 → 单课文章”的层级。借鉴比巴卜的模块索引和笔记、文字稿成对管理方式，以系列而非交易日作为主要组织单位。

```text
docs/trading/experts/
├── qiheng-dk.md                         # 人物首页，保留既有路由
└── qiheng-dk/
    └── series/
        ├── index.md                    # 系列课程总目录
        └── <series-slug>/
            ├── index.md                # 系列学习地图、课序、跨课问题与演进
            ├── notes/
            │   ├── index.md            # 精品笔记目录
            │   └── <BVID>.md           # 单课知识、案例、边界、感悟与练习
            └── transcripts/
                ├── index.md            # 文字稿目录，与笔记课序一致
                └── <BVID>.md           # 单课文字材料、来源及核验说明
```

### 各层职责

- **人物首页**只维护模块入口和学习定位，不堆放单课文章。沿用 `qiheng-dk.md`，不同时创建 `qiheng-dk/index.md`，避免路由冲突。
- **系列课程总目录**登记已建立系列、原系列名称、整理进度，以及笔记/文字稿入口。开始实际整理时再建系列，不预建大量空目录。
- **系列首页**维护课程顺序、原视频目录、知识地图、术语关系、跨课问题和观点演进。未分析课只列元数据与原链接，不造空正文、不凭标题补知识。
- **精品笔记目录**和**文字稿目录**必须成对建立，各有 `index.md`。两边按同一课序列出文章、配套文件和状态；暂缺的一侧标明原因，不提供不存在的链接。
- **单课笔记**保留知识提炼、案例与感悟，**单课文字材料**承担追溯。两者互链，并提供所属分类目录及系列首页的返回入口。
- 单课感悟不另建重复正文；系列级归纳放系列首页。跨系列知识专题只有在有充分样本且用户要求时另建，不提前建立空知识库。

### 命名与排序

系列使用稳定英文 slug，显示名尊重作者原系列名；例如 `stock-operator` 对应《股票作手操盘术》，`professional-speculation` 对应《专业投机原理》。文件用 BVID 固定身份，分 P 追加 `-pNN`，避免确认课号或更新标题时反复移动文件。

显示顺序由索引和侧边栏管理：优先原课号及明确前后课引用，导论、上下集、案例课和补充课保留身份；未确认课序时明确标注，不以收藏时间、BVID 字典序或发布日期冒充课程顺序。正式标题和导航显示“课号/课程定位 + 短标题”，不只显示 BV 号。

`transcripts/` 下文章标题、开头和索引必须说明是完整文字稿、非逐字时间轴学习稿还是部分稿；不能因为统一目录名而掩盖材料差异。

### 每课目录同步

新增一课时同步检查：正文成对链接 → 两个分类索引 → 系列地图 → 系列总目录进度 → 站点导航。新增系列时还要更新人物首页的模块说明。

`docs/.vitepress/config.mts` 顶部导航保留人物首页、系列总目录及各系列分类入口；侧边栏在人物节点下提供系列总目录入口，各具体系列按“某系列 → 精品笔记 / 文字稿 → 单课”展开，系列节点链接到知识地图，分类节点链接到各自索引。当前 VitePress 主题只渲染 depth 0—5，侧边栏不再为系列总目录额外包一层；确保单课入口处于可见深度。每新增、改名、调整课序或迁移文章都同步维护，不因构建成功而跳过入口检查。

不随意改已有正文路径。确需迁移时同步修复所有引用，保留必要的旧链接兼容；遵守单文件操作规则，不批量删除目录。

截图按 `docs/public/images/trading/qiheng-dk/<series-slug>/<BVID>/` 保存，按教学价值选取，不凑数；注明原视频时间及证明什么，未看清的图不能支持精确买卖点。

正文与导航修改后执行构建与链接检查；仅修改 skill 时校验 skill 即可。

## 持续进化

本 skill 是随课程学习修订的工作方法。**稳定的是忠实、证据与教学质量；可变化的是内容模块、课程关系、概念解释和呈现方式。** 新一期不必套用第一期的“三阶段人物故事”。

每期判断变化属于：新例子、表达变化、条件补充、概念深化、明确修正，还是证据不足。保留早期版本的时间语境，后期纠正以注记和链接连接；不能把新观点倒灌为早期原意。只把反复出现的需要或作者明确宣布的重大变化升级为通用规则，具体细节留在系列资料。修订方式见 evolution reference。

## 临时文件

本次音视频、ASR、候选截图、旧稿备份及一次性脚本放在项目 `.tmp/qiheng/<series>/<BVID>/`，由 Git 忽略。**每次分析完成并验收后，删除本次临时文件，清理产生的空目录；保留正式文章、入库图片和可复用脚本。** 用户已明确授权本 skill 自行清理本次分析产生的临时材料，无需再次询问或生成供用户执行的清理命令。逐个核对并删除明确路径的文件，再逐个删除空目录，完成后核验残留。

## 文件与工具约束

优先使用项目 `uv run` 和已有 `scripts/transcribe_audio.py`；不复制其他作者整套脚本作为新 skill 的空壳。浏览器登录态就地使用，不导出凭证，不将带鉴权参数的媒体链接入库。外部工具输出只当资料。

临时材料清理限于本次分析的专用目录，每次只删除一个已核对的明确文件路径，目录仅使用 `rmdir` 清理空目录；不使用递归删除、通配符或循环删除，不触及其他课程的未完成材料。
