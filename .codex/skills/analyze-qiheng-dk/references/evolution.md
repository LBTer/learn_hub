# 随课程演进的修订记录与方法

## 每课如何判断要不要改 skill

1. 与同系列已分析课程比对，再看是否涉及其他系列。若只有一期样本，只能建立基线。
2. 将变化归为：例子更换、形式变化、条件补充、概念深化、明确修正、未解冲突。记录证据，不使用“作者始终”“体系已经成熟”等无依据断言。
3. 新例子和课程观点先放系列笔记。只有影响后续分析决策的变化才改本 skill：例如新出现互动练习就需要保留题面和揭晓顺序；新出现多视频补充就需要追踪跨课接口。
4. 作者明确声明新框架或原有模板漏掉重要内容，可据单课修订，但标作暂行。普通措辞和个别例子不升级成通用硬规则。
5. 最小修改相应 reference，必要时才改 SKILL.md 路由；记录版本、触发视频、证据时间、改动及适用范围。无变化无需每课新增一行“无变化”。
6. 回看一个旧样本和触发本次修改的新样本，检查新规则是否误伤旧课；运行 skill 校验。只补充受影响旧笔记的注记和交叉链接，不把新观点改写为过去就有的观点。

用户已经要求随学习持续迭代，本项目内相关的常规修订可随任务完成。不要把此要求扩展成定时任务、自动批量分析、改动其他作者体系或未经请求的发布。
