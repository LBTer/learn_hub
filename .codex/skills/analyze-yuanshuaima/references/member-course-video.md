# 袁帅马充电会员体系课程工作流

## 适用范围

用于有明确合集、课程顺序或系统教学目标的会员课程，包括趋势结构、主力行为、量价、均线、筹码、盘口、买卖点、仓位、心态和案例课。开始前核验视频标题、课程编号、所属合集、发布时间、时长、BVID、CID、会员可见性和合集顺序。

若视频主要围绕一只或少数几只个股的历史走势与后续参与，改读 [member-trend-case.md](member-trend-case.md)。不要仅凭“教学”“课程”等标题建立体系课程；实际内容必须呈现规则、能力目标或课程依赖。

## 三层产物

- **课程文字稿负责完整**：保存定义、讲解顺序、全部案例、操作演示、前后补充和课程引用。
- **单课学习笔记负责提炼**：呈现本课能力目标、核心规则、决策流程、使用边界和少量典型案例。
- **合集体系地图负责跨课结构**：维护学习顺序、模块关系、稳定术语、前置依赖和跨课待验证问题。

每课生成：

1. `member-topics/<course-series>-transcripts/NN-course-slug.md`。
2. `member-topics/<course-series>/NN-course-slug.md`。
3. 更新两个课程索引、`member-topics/index.md`、人物主页和 VitePress 侧边栏。
4. 更新 `member-topics/<course-series>/index.md` 中的课程体系地图。

课程编号以视频标题和合集顺序为准，使用两位数字。标题没有编号的旁支内容标为“旁支专题”，不得擅自插入主课程编号。截图保存到 `docs/public/images/trading/yuanshuaima/member-<course-series>/NN/`。

## 强制执行顺序

1. 制作原始提取稿，再制作覆盖全片的课程文字稿；不得同时撰写学习笔记。
2. 核实课程中提到的股票名、代码、案例图表位置和课程顺序；无法确认时保留上下文并标记“待核”。
3. 确认概念定义、讲解路径、操作步骤、案例、反例、新手误区、课程引用和使用边界均已纳入，将文字稿冻结。
4. 只以冻结文字稿生成单课学习笔记并更新合集体系地图。
5. 完成关键帧、索引、侧边栏、构建检查和逐文件临时清理。

文字稿冻结前禁止创建或预写学习笔记。外部信息只用于元数据、核名和图表定位，不对课程观点或案例逻辑做额外补写。文字稿实质修订后必须同步复查学习笔记和体系地图。

## 课程文字稿要求

沿用主 skill 的两阶段规则，并重点保留：

- 概念首次出现时的完整定义和作者原始解释顺序。
- 前置知识、推导过程、类比、反例、自我修正和有信息量的重复。
- 看图路径、决策步骤、工具设置和操作顺序。
- 每个案例的市场背景、图形条件、作者为何选择、结论和边界。
- 新手误区、禁止事项、纪律要求和作者强调的优先级。
- 与前后课程的引用、补充、冲突和依赖关系。

文字稿末尾根据实际内容附“本课术语表”“本课全部案例与股票提及表”“与其他课程的关联表”和“待后续课程补全的问题”。

## 单课学习笔记筛选

冻结文字稿后依次回答：

1. 本课希望学习者获得什么判断能力？
2. 作者给出了哪些明确规则、条件和优先级？
3. 这些规则组成怎样的看图或决策顺序？
4. 每条规则适用于什么场景，如何失效或被误用？
5. 哪 2 至 4 个案例最能证明规则、构成对照或揭示反例？
6. 本课依赖哪些前置知识，又向后续课程输出什么能力？

核心规则通常控制在 3 至 5 条。完整授课过程和补充案例留在文字稿；单课笔记不重复维护全局课程总纲。关键截图通常为 4 至 8 张。

## 合集体系地图

在 `<course-series>/index.md` 中根据已完成课程持续维护：

- 课程顺序与学习路径。
- 趋势结构、主力行为、量价、均线、筹码、盘口、仓位和心态等模块。
- 模块之间的前置依赖和调用关系。
- 从选股、观察、等待、参与、持有到退出的决策链。
- 稳定术语及作者定义。
- 规则、例外、适用条件和失效边界。
- 已讲清、尚未讲清和后续课程待验证的问题。

只记录课程正文已经支持的关系，不根据课程标题补写作者尚未表达的方法。单课笔记只写简短的前后接口，全局关系统一写入体系地图。

## 与技术点学习的边界

- 课程目录忠实还原作者的课程定义、案例和内部关系。
- `technique-notes/` 用于多个视频和后续走势验证后的二次研究。
- 不把单课规则直接写成跨期稳定结论，也不把分析者归纳混入作者课程。
